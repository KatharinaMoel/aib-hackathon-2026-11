Empty on purpose: what we measure depends on the idea, which the team picks at the start.

Once the idea is picked, write down here:

1. **The case list** – 5 to 10 inputs we run after every change (recorded MCP responses in `data/`, git-ignored).
2. **What "better" means** – the number or check that tells a good result from a bad one.
3. **The command** – it also goes into `AGENTS.md`, "Stack and commands".

Every prompt or logic change names what it improves, never a single case (`AGENTS.md`, rule 11).
